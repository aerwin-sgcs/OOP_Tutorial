What on earth is "object-oriented programming"?

Let's find out with zero code and zero jargon. Just read — it takes about 3 minutes.

You don't need to remember anything on this page. You don't need Python installed. Nothing here can go wrong. Just scroll.

IDEA 1 OF 4

It's just a way of organising code around things.

Older code was a long list of instructions — do this, then this, then this. Object-oriented programming (OOP) organises code around things instead: a player, a car, a bank account, a dog.

Each "thing" keeps its own information and the actions it can do, all in one tidy bundle. That's the whole idea. Everything else is just detail.

IDEA 2 OF 4

A class is a blueprint. An object is the real thing built from it.

THINK OF A COOKIE CUTTER The cookie cutter is the class — one shape, made once. Every cookie you press out is an object — real, and you can make as many as you like. Same shape, but each cookie is its own thing.

Blueprint for a house → the actual houses built from it. One class, many objects. That's the vocabulary that trips people up, and now you've got it.

IDEA 3 OF 4

Here's what it looks like — don't worry, just glance.

A blueprint for a dog. Read it like a sentence, you don't have to type it:

class Dog:              # the blueprint
    def __init__(self, name):
        self.name = name    # each dog remembers its name

    def bark(self):        # something a dog can DO
        print(self.name + " says woof!")

↑ A dog knows its name (information) and can bark (an action). Bundled together.

Now make some real dogs from the blueprint:

rex = Dog("Rex")     # an object
bella = Dog("Bella")  # another object
rex.bark()             # Rex says woof!
bella.bark()           # Bella says woof!

One blueprint, two real dogs, each with its own name. That's OOP. You just read it.

IDEA 4 OF 4

The "big three" words, in one line each.

Every OOP course throws these at you. Here they are with the scary taken out:

EncapsulationKeep a thing's private stuff private. Like a car — you use the pedals, you don't touch the engine.
InheritanceA new blueprint can borrow from an old one. A Puppy is a Dog — no need to re-explain barking.
PolymorphismSame command, different result. Say "make a sound" — a dog barks, a cat meows.

That's it. You now understand what the whole course is about, before writing a single line.
